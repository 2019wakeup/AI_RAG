# 企业资料语料（`data/corpus/enterprise/`）

> **一句话**：这里是**脱敏样例**，不是可追溯的企业数据。原始企业数据集从未进入本仓库，任何一条记录都无法通过公开来源核对。
> 本文是 `NOTICE.md` §2 第 2 条在本目录的展开，用于回答「这条证据能不能当硬依据」。

## 2. 单条记录的字段

```json
{
  "schemaVersion": "1",
  "id": "ent-binder-001",
  "category": "binder",
  "type": "胶结料（沥青）",
  "name": "70# 直馏沥青",
  "specs": { "针入度": "72 (0.1mm)", "软化点": "47.6℃" },
  "sourceRef": "企业数据：再生沥青混合料数据集-材料与指标（70# 直馏）",
  "text": "……",
  "tags": [],
  "relations": []
}
```

`id` 形如 `ent-<category>-<nnn>`；`sourceRef` 是**文字说明**，不是 DOI 或规范号。

## 3. 脱敏与不可追溯（核心约定）

1. **原始数据不在仓库**：企业提供的原始表格/接口/数据库从未提交，仓库只保留脱敏后的规格、关系与实验室指标样例。
2. **`sourceRef` 不可核对**：它描述的是「某企业某批数据，已脱敏」，**不存在公开可访问的原始出处**；这与规范号（`JTG F40-2004`）或 DOI 的可验证性有本质区别。
3. **企业名称、牌号、成本、实测值均为示例**：不得据此反推真实配方，也不得当作某产品的真实性能。
4. **不计入「可溯源原文证据」**：全仓的「原文 3 类」= 规范条文 / 论文全文 / 定量表格；企业资料与知识条目同属**二次加工文本**。

## 4. 对问答与评测的约束

- 问答回答若引用了 `docType = enterprise` 的证据，答案中必须同时说明其**不可追溯**，不得作为唯一依据给出硬结论；
- QA 金标准（`data/golden/qa.json`）的正样本**只取** `standard` / `literature-full` / `table` 三类原文语料，**禁止**用 `enterprise` 或 `knowledge` 作为 goldDocIds（见 T23 验收③）；
- 评测报告中，涉及企业资料的结论需单列，不得与原文类证据混算同一指标。

## 5. 修改本目录时

1. 新增记录必须带 `sourceRef` 文字说明，且说明中不得出现可识别真实企业的信息；
2. 新增后重跑 `pnpm exec tsx scripts/validate-corpus.ts`（该脚本校验字段与 `sourceRef` 非空）；
3. 条数变化需同步 `NOTICE.md` §2 的规模列。
