# 索引构建与发布（reproducible cache）

> 索引是**可重建缓存**，不是代码：`data/index/**`、`data/db/**`、模型缓存都不入库（`.gitignore` 已排除）。
> 真相源永远是 `data/corpus/**`。本文给出「语料变更 → 重建 → 自检 → 指纹 → 发布」的完整流程。

## 1. 路径约定（唯一派生处）

服务端、评测脚本、构建脚本使用同一套名字（`apps/server/src/config.ts` 的 `vectorStorePaths()`）：

| 产物 | 路径 | 说明 |
|---|---|---|
| LanceDB 向量库 | `data/index/lancedb/` | 默认后端（ANN + FTS） |
| SQLite 降级库 | `data/index/app.db` | 零原生依赖后端；**服务端与评测脚本统一用它**（M0 时代的 `sqlite.db` 已废弃） |
| 构建清单 | `data/index/manifest.json` | 每块一行：docId / contentHash / docType；幂等与换模型重建的依据 |
| 模型缓存 | `data/index/hf-cache/` | transformers.js 本地模型（约 1.6 GB，不入库） |
| 索引指纹 | `docs/experiments/index-fingerprint.json` | **入库**，记录本次发布的索引身份 |

> T04 修掉的坑：旧版服务端 sqlite 后端读 `sqlite.db`（空库），而评测脚本读 `app.db`（11,087 块），
> 形成「三份不同的库」。现在两处都从 `vectorStorePaths()` 派生，`app.db` 是唯一 sqlite 文件名。

## 2. 构建（首次或语料变更后）

```bash
# 首次：11,014 块（T15 清洗后），e5-small（384 维），实测约 700 s；需能下载模型（国内建议 HF 镜像）
HF_ENDPOINT=https://hf-mirror.com \
EMBEDDING_MODEL=multilingual-e5-small \
pnpm build:index -- --rebuild --backend=lancedb --model=multilingual-e5-small
```

- **幂等**：未变更的块按 `contentHash` 跳过；`--rebuild` 才全量重嵌；
- **换模型必须重建**：manifest 的 `dim/modelVersion` 变化会触发全量重建（防止「e5-small 建的索引配 bge-m3 查询」的静默错配）；
- 想同时保留 sqlite 后端：`pnpm build:index -- --rebuild --backend=sqlite --model=multilingual-e5-small`（产物 `data/index/app.db`）。

## 3. 自检（提交前必跑）

```bash
EMBEDDING_MODEL=multilingual-e5-small pnpm exec tsx scripts/build-index.ts --check
```

输出形如：

```
index-check: count=11014 model=Xenova/multilingual-e5-small dim=384 backend=lancedb
  store: count=11014 docTypes={"knowledge":94,"standard":57,...,"table":934,"enterprise":56}
  path: /…/data/index/lancedb
  manifest: /…/data/index/manifest.json
  ✅ 自检通过
  指纹已写入：/…/docs/experiments/index-fingerprint.json
```

`--check` **不重建、不加载嵌入模型**，只做四项一致性判定：

1. manifest 存在且 `chunks > 0`；
2. 向量库实际 `count` == manifest 的 chunk 数（库与清单同源）；
3. manifest 的 `dim` == `EMBEDDING_MODEL` 的期望维度（384 / 1024）；
4. manifest 的 `embeddingModel` 与所选模型名匹配。

任一不满足 → 打印问题清单并 **exit 1**。可选参数：`--fingerprint=<path>` 改指纹位置、`--no-fingerprint` 不写指纹。

## 4. 指纹（入库的发布凭据）

`docs/experiments/index-fingerprint.json` 字段：

| 字段 | 含义 |
|---|---|
| `count` | 索引块数（当前 **11,014**） |
| `model` / `modelVersion` / `dim` | 嵌入模型与维度（`Xenova/multilingual-e5-small` / `3.8.1` / `384`） |
| `backend` | `lancedb` \| `sqlite` |
| `dbPath` / `manifestPath` | **仓库相对路径**（可移植，不含本机绝对路径） |
| `manifestHash` | manifest 文件 sha256（索引身份的强校验） |
| `pipelineRev` | 构建流水线版本（本地无 git 时为 `unknown`，见遗留项） |
| `docTypes` | 六类语料分布 |
| `command` / `generatedAt` | 生成命令与时间；**二次运行只有 `generatedAt` 变化** |

## 5. 发布流程（语料变更后由 A 执行）

```bash
# ① 语料变更合入后（E 的 T15）→ 全量重建
HF_ENDPOINT=https://hf-mirror.com EMBEDDING_MODEL=multilingual-e5-small \
  pnpm build:index -- --rebuild --backend=lancedb --model=multilingual-e5-small

# ② 自检 + 刷新指纹（重跑两次，第二次应只有 generatedAt 变化）
EMBEDDING_MODEL=multilingual-e5-small pnpm exec tsx scripts/build-index.ts --check
EMBEDDING_MODEL=multilingual-e5-small pnpm exec tsx scripts/build-index.ts --check

# ③ 回归：混合检索金标准（应 38/38、mean recall@5 = 0.9187 ±0.001）
EMBEDDING_MODEL=multilingual-e5-small pnpm exec tsx scripts/golden-eval.ts lancedb --json

# ④ 只提交指纹，不提交索引
git add docs/experiments/index-fingerprint.json && git commit -m "chore(index): 刷新索引指纹"
```

> 发布窗口：①完成前其他人**不要**跑会写 `data/index` 的脚本；`data/index/**`、`data/db/**` 永不入库（**不要改 .gitignore**）。

## 7. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `--check` 报 count 不一致 | 向量库与 manifest 不同源（例如只重建了一半） | `--rebuild` 全量重建后再 check |
| `--check` 报维度不匹配 | 换模型没重建 | 用新模型 `--rebuild`；或改回建索引时的模型 |
| `--check` 报向量库为空 | `data/index/` 不存在（新克隆） | 先 `pnpm build:index` |
| 重建很慢（> 15 min） | 串行嵌入 + CPU 推理，11k 块属正常 | 保持 `EMBEDDING_MODEL=multilingual-e5-small`；bge-m3（1024 维）更慢 |
