# 接口契约（schema ↔ 路由 ↔ 前端消费点）

> 契约唯一真相源：`packages/contracts/src/schemas.ts`（zod）+ `registry.ts`（表单字段）+ `openapi-components.ts`（对外组件登记）。
> 所有消息 `.passthrough()` + `schemaVersion: '1'`，演进规则为**只增不改**。
> `/openapi`（`GET /openapi`）的 `components.schemas` 由 `OPENAPI_COMPONENTS` 生成，测试断言两边名字集合一致——**任何一方漏登记都会红**。

## 1. 对外响应体组件（`OPENAPI_COMPONENTS`，9 个）

| 组件名 | 对应 schema | 说明 |
|---|---|---|
| `SceneInput` | `SceneInputSchema` | 推荐入参：气候/交通/路面/病害/约束 13 字段 |
| `TargetProfile` | `TargetProfileSchema` | 目标性能与优先级（模块 A 输出） |
| `RecommendationReport` | `RecommendationReportSchema` | 报告主体：候选/证据/基准/章节/步骤/降级标记 |
| `Candidate` | `CandidateSchema` | 单候选：配方 + 8 维雷达 + 11 项实测指标 + 得分分解 |
| `EvidenceRef` | `EvidenceRefSchema` | 证据引用（**与 SearchHit 同一 schema 对象**） |
| `CorpusChunk` | `CorpusChunkSchema` | 语料块：`text` 原文 + `provenance` 七字段 |
| `SearchHit` | `SearchHitSchema` | 检索命中 = `CorpusChunk` + `score` |
| `CaseSeed` | `CaseSeedSchema` | 典型案例（场景 + 期望方向） |
| `KnowledgeEntry` | `KnowledgeEntrySchema` | 材料知识条目（42 条 / 94 关系） |

## 2. 路由 → 契约 → 前端消费点

| 路由 | 请求 | 响应 | 前端消费点 |
|---|---|---|---|
| `POST /api/v1/recommend` | `SceneInput` | `RecommendationReport` | `apps/web/src/views/RecommendView.vue`（候选卡/雷达/基准表/证据链）、`stores/recommend.ts` |
| `POST /api/v1/recommend/stream` | `SceneInput` | SSE：`step` / `section` / `done`（载荷为 `RecommendationReport` 片段） | `api/client.ts` 流式消费 + `ReportPanel` |
| `GET /api/v1/cases`、`/api/v1/cases/:id` | — | `CaseSeed[]` / `CaseSeed` | `views/CasesView.vue`（一键回填场景） |
| `GET /api/v1/health` | — | `{ vectorStore{backend,count,ok}, llm{configured}, adapters{a,c} }`（无独立 schema，内联） | `views/WelcomeView.vue`、`App.vue` 状态角标 |
| `POST /api/v1/feedback` | 任意 JSON（stub，不回写） | `{ received: true }` | 暂未接前端（模块 E 预留） |
| `GET /api/v1/kb/stats` | — | `{ count, docTypes, backend }` | `views/KnowledgeView.vue` |
| `POST /api/v1/kb/search` | `{ query, topK?, docTypes? }` | `SearchHit[]`（原文 + provenance） | `components/KbSearchBox.vue` |
| `POST /api/v1/kb/documents` | JSON 或 multipart（PDF 走 pdf-parse） | `{ added, chunks }` | `KnowledgeView.vue` 上传入口 |
| `POST /api/v1/kb/rebuild` | — | `{ added, skipped, total }` | `KnowledgeView.vue` 重建按钮 |
| `POST /api/v1/chat` | `{ question, history?, reportContext? }` | SSE `{delta}` + `done`（**不检索、无引用**，仅报告上下文对话） | `components/ChatDock.vue` |
| `POST /api/v1/qa` 🚧 | `QaRequest` | `QaResponse`（骨架期 501 `status:"not_implemented"`） | `views/QaView.vue`（T13 起） |

> 图例：🚧 = 骨架已就位、实现由 S1/S2 任务补齐（见 `docs/plan/task-topology.md`）。

## 3. 关键字段约定（评测会查）

| 字段 | 约定 |
|---|---|
| `SearchHit.text` | **原文片段全文**，不得只留标题/摘要；问答 `citations[].snippet` 直接取它 |
| `SearchHit.provenance` | 七字段：`sourceDocId / contentHash / embeddingModel / modelVersion / dim / pipelineRev / embeddedAt` |
| `RecommendationReport.evidenceIds` | 只能引用 `evidence[]` 里存在的 id（服务端白名单过滤） |
| `QaResponse.citations[].n` | 从 1 起连续、无重复；答案里的 `[n]` 必须落在该区间 |
| `QaResponse.needInfo` | `string[]`（追问项），**不得**改成结构化对象（破坏性变更需双端 PR） |
| `llmStatus` | `ok | degraded`；LLM 不可用（未配置/402/超时）必须降级而非报错 |
