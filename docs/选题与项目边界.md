## 1. 课程题目与本项目的对位

### 1.1 题目出处

- **课程**：研究生《课程设计》
- **方向**：方向 1 · 工程实践题目 1
- **题目**：**带证据引用与可信拒答的领域知识库问答系统**
- **本项目**：仓库 `AI_RAG`，产品中文名 **沥知问答**，领域为**沥青路面养护材料**
- **课程下发文件**：《课程设计题目》（统一要求 + 3 个方向共 6 个题目）。本节的「题目原文要点」是按该文件整理的要求摘要，逐条对位见 §1.2。

### 1.2 题目要求逐条对位

题目要求可拆成 5 条硬要求。下表的「现状」只描述**本仓库已提交的代码**，不把计划中的能力算作已实现。

| # | 题目原文要点 | 本项目的做法 | 落点 | 现状 |
|---|---|---|---|---|
| 1 | **选择一个明确的领域**，构建领域知识库 | 领域 = 沥青路面养护材料。语料 6 类：规范条文 / 论文题录 / 论文全文 / 定量表格 / 材料知识条目 / 企业资料；域外文档（约 12% 的表格）需物理剔除 | `data/corpus/` | ✅ 语料已就绪（11,143 块 / 395 文档）；🟡 域外表格剔除与碎块过滤待做（E） |
| 2 | **基于文档回答问题**（检索增强生成） | 问题 → 混合检索（BM25 + 向量，RRF 融合）→ 证据选择 → 受证据约束的生成 → 引用绑定 | `POST /api/v1/qa`、`apps/server/src/qa/` | 🚧 端点骨架已提交（返回 `501 status=not_implemented`），检索/生成/引用待实现（B） |
| 3 | **返回原始证据片段**（不是只给文档标题） | 每个 chunk 自带 `text`（原文片段）与 7 字段 provenance；引用 `snippet` 直接取 chunk 原文，禁止截成标题 | `SearchHit` / `QaCitation` 契约；`EvidencePanel.vue` / `EvidenceContent.vue` 等前端组件 | ✅ 数据结构与检索侧已具备；🚧 问答页的引用展示待实现（D） |
| 4 | **证据不足时可信拒答**（不编造） | 拒答判据：命中数 / 原始相似度 / 证据覆盖率 / LLM 判定证据不足；信息不足时返回追问项 | `apps/server/src/qa/{refusal,clarify}.ts`；`QaRefusalReason` 枚举 | 🚧 契约与枚举已定义，策略未实现（C） |
| 5 | **至少三种检索方案对比** | 纯 BM25 / 纯向量 / 混合 RRF 三方案在同一金标准上评测；重排可选 | `scripts/golden-eval.ts`、`HYBRID_WEIGHTS`、`RERANK` | 🟡 三方案口径可跑（38 条金标准），但缺 `--vector/--rerank` 显式开关与结果落盘（F） |

> **口径提醒**：`/api/v1/chat` 只是把推荐报告 JSON 塞进 prompt 的多轮对话，**不检索、无引用**，不能当作「基于文档问答」；问答能力统一走 `/api/v1/qa`。

### 1.3 一句话叙事（答辩、报告开头用）

> 本项目在真实的沥青养护材料语料上，构建**带原文证据引用与可信拒答的领域问答系统**；并保留其下游应用——材料方案推荐——作为「问答与证据链能力在工程场景中的落地验证」。

## 2. 与旧「推荐系统」定位的边界

### 2.1 这个仓库的前身

仓库代码的前身是一个「沥青材料智能推荐系统」：输入养护场景（气候/交通/病害/约束），经**六步确定性 pipeline** 输出 Top-5 材料方案、8 维雷达图、规范基线对比与推荐报告，RAG 只在最后一步为每个候选方案附加证据。该链路代码完整保留，可正常演示。

### 2.2 新定位：问答是主交付，推荐是下游应用

| 维度 | 推荐链路（遗留下游应用，**冻结**） | 问答链路（**本次课程设计主交付**） |
|---|---|---|
| 入口 | `POST /api/v1/recommend`、`/api/v1/recommend/stream` | `POST /api/v1/qa`（规划中前端 `/qa` 页面） |
| 是否检索 | **不是 RAG 检索**：关系表 SQL 硬过滤 + 配方组合，证据是后置附件 | **RAG 检索**：BM25 + 向量余弦 → RRF(k=60) 融合 → 证据选择 |
| 输出 | 报告 JSON：候选方案 / 雷达 / 基线 / 章节文案 / 证据列表 | 答案文本 + `[n]` 引用 + 拒答原因 + 追问项 |
| LLM 角色 | 文案与解释（失败即降级模板），不改变数值结论 | 受证据约束的生成（不可用时降级抽取式答案） |
| 证据要求 | 每个候选方案挂若干证据 | 答案的**每个事实性断言**都要落到引用 |
| 评测 | 5 案例端到端 + 确定性复现 + 三档降级 | QA 金标：答案正确率 / 引用正确率 / 拒答准确率 / 时延 |
| 保留价值 | 证明问答与证据链能落到真实工程流程 | 课程题目的核心要求 |

**冻结约定**：推荐链路（`apps/server/src/orchestrator.ts`、`apps/server/src/relation/**`、`apps/web/src/views/RecommendView.vue`）**不再新增功能**，只允许修 bug；所有新能力进问答链路。若确需改动，先改 [任务拓扑](plan/task-topology.md) 的写域约定并评审。

### 2.3 品牌更替

产品中文名统一为 **沥知问答**；前端 UI 的历史品牌文案由 D（前端问答体验）统一替换。旧项目的历史材料见 [docs/archive/](archive/README.md)，不再对外使用旧品牌。

## 5. 术语表

| 术语 | 含义（本项目口径） |
|---|---|
| **chunk（知识块）** | 入库的最小检索单元。本项目 6 类语料共 11,143 块，块 ID 形如 `k-binder-001:3`、`jtg-5142-2019:2`、`litfull-004:12`、`table-012-3`、`ent-binder-001:0` |
| **docId / sourceDocId** | 块所属文档的稳定标识（知识条目 `k-*`、规范 `jtg-*`、题录 `lit-*`、全文 `litfull-*`、表格 `table-<docSeq>`、企业条目 `ent-*`）。金标准按 **doc 级** 计算 recall |
| **原始证据片段** | 检索返回的 `SearchHit.text`：规范条文正文、论文全文节块、表格 Markdown 等**原文**；知识条目与企业资料为模板拼装的**整理文本**，须区分 |
| **provenance（溯源信息）** | 每个 chunk 的 7 字段元数据：`sourceDocId` / `contentHash` / `embeddingModel` / `modelVersion` / `dim` / `pipelineRev` / `embeddedAt`，用于防「旧向量 + 新查询」的静默漂移 |
| **引用（citation）** | 答案中的 `[n]` 角标，绑定到本次检索的某个 chunk；`QaCitation.snippet` 必须是该 chunk 原文，不得只给 id 或标题 |
| **证据（evidence）** | 可被引用、可展开原文的检索命中集合；推荐链路里指挂在候选方案下的证据附件，问答链路里指进入生成上下文的片段 |
| **拒答（refusal）** | 证据不足以支撑回答时明确说「不知道」，返回 `refused=true` + `refusalReason`（无命中 / 低相关 / 域外 / 证据不足 / 生成不可用），**不编造答案** |
| **追问（needInfo）** | 问题缺少必要信息（气候、荷载、病害、层位等）时，不硬答，返回需补充的信息项列表（`needInfo: string[]`） |
| **检索金标准（golden）** | `data/golden/golden.json` 的 38 条查询 + 期望文档集合（共 91 个期望文档），用于回归检索能力；口径为 doc 级 recall@5 |
| **BM25** | 关键词检索打分。SQLite 后端用 FTS5 trigram 索引（兼容中文子串），LanceDB 后端用其 FTS 索引 |
| **向量检索** | 用嵌入模型把 chunk 与查询编码为向量，按余弦相似度召回 |
| **混合检索** | 两路召回结果用 RRF 融合；`HYBRID_WEIGHTS=bm25,vec` 可调权重，`0,1` 即纯向量 |
| **RRF（Reciprocal Rank Fusion）** | 融合公式 `score = Σ wᵢ / (k + rankᵢ)`，本项目 `k=60`，无需归一化两路分数 |
| **重排（rerank）** | 在 RRF 之后用 LLM 对候选做精排；`RERANK=off` 或 LLM 不可用时回退 RRF 原序 |
| **嵌入模型 / 维度** | 本项目默认 `multilingual-e5-small`（384 维）；备选 `bge-m3`（1024 维）、`multilingual-e5-base`（768 维）。**换模型必须重建索引** |
| **索引（index）** | `data/index/` 下的向量库与 manifest；**不入库**，首次运行 `pnpm build:index` 重建（约 729 s） |
| **幂等入库** | 按 `chunkId + contentHash` 判断：内容未变跳过、内容变化重嵌、语料删除同步删除 |
| **降级（degraded）** | 依赖不可用时的确定性替代路径：LLM 挂 → 模板/抽取式文案；模型不可用 → 纯 BM25；LanceDB 初始化失败 → SQLite；A/C 服务不可达 → 内置 mock |
| **闭集评测** | 检索金标准的期望文档全部在索引内（91/91），属于闭集评测，不能外推为开放域效果 |
| **验收基线** | 整理时的实测数字：索引 11,143 块 / 395 文档、测试 334 passed / 3 skipped、混合检索 38/38 达标（mean recall@5 0.9187） |

## 6. 已知局限

如实登记，报告中须主动交代（不是「待修 bug」，而是本阶段的能力边界）：

1. **语料领域纯度不足**：`data/corpus/tables/tables.json` 中约 **12%（约 128 / 1,041）** 的表格来自域外文献（LLM/知识图谱/DPR/XGBoost 等方法类论文），会稀释「明确领域」的论证，须物理剔除或在数据说明中显式筛选（E，T15）。
2. **企业数据不可追溯**：`data/corpus/enterprise/*.json` 的 `sourceRef` 只有文字说明，原始数据集与 URL 不在仓库；56 块企业语料只能作为脱敏样例使用。
3. **部分全文块质量差**：OCR 噪声导致少数文献章节块 **<30 字**，检索命中后作为证据价值低，须过滤（E，T16）。
4. **问答链路尚未实现**：`/api/v1/qa` 目前只返回 `501 not_implemented` 骨架；拒答/追问策略、前端问答页、QA 金标均待建，这是本课程设计的核心待交付项（B/C/D/E/F）。
5. **LLM 依赖有余额风险**：DeepSeek 余额为 0 时接口返回 HTTP 402，生成/重排/场景抽取会降级为模板与 RRF 原序；**评测数字须注明是否处于降级模式**。
6. **评测是闭集且门槛偏松**：38 条金标准的 91 个期望文档全部在索引内；`minRecallAt5` 中有 18 条为 1.0，存在「按结果标定门槛」的风险，换模型/换索引后不保证 38/38。T24 将把 38 条拆为 **dev 28 / held-out 10**，报告口径为「dev 28/28 + held-out 10 条单独报告」（当前尚未执行）。
7. **索引与语料强绑定**：换嵌入模型或改切块规则必须全量重建（约 729 s），仓库不携带预建索引，首次运行需联网下载模型。
