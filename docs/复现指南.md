# 复现指南：从零到跑通

> **目标**：在一台干净的 Linux 机器上，从克隆仓库开始，按顺序执行本文命令即可复现「索引构建 → 服务启动 → 前端演示 → 单测 → 检索评测 → 端到端」。
> **约定**：未特别说明时，**工作目录 = 仓库根目录**；命令可直接复制执行；首次运行需要联网下载依赖与嵌入模型。
> **配套**：[README](../README.md)（定位与命令速览）｜[数据来源与清洗说明](数据来源与清洗说明.md)｜[NOTICE](../NOTICE.md)

## 0. 环境基线

| 项 | 要求 | 本次实测环境 |
|---|---|---|
| 操作系统 | Linux x64（macOS 亦可，Windows 建议 WSL2） | Linux x64 |
| Node.js | **≥ 24**（SQLite 降级后端使用 Node 内置 `node:sqlite`） | v24.21.0 |
| pnpm | **12.x**（`packageManager: pnpm@12.11.2`） | 12.11.2 |
| 磁盘 | 预留 **≥ 2 GB**（依赖 + 模型缓存 + 索引） | — |

```bash

pnpm -v    # 期望 12.x；未安装时：corepack enable && corepack prepare pnpm@12.11.2 --activate
```

## 3. 构建索引（首次必做，约 12 分钟）

仓库**不包含**预建索引（`data/index/`、`data/db/` 均被 `.gitignore` 排除）。首次运行必须构建：

**工作目录**：仓库根

```bash
HF_ENDPOINT=https://hf-mirror.com \
EMBEDDING_MODEL=multilingual-e5-small \
pnpm build:index -- --rebuild --backend=lancedb --model=multilingual-e5-small
```

- **环境变量**：`HF_ENDPOINT`（模型镜像）、`EMBEDDING_MODEL`（与 `--model` 保持一致）
- **预期输出**（示意，`pipelineRev` 为 git 短 SHA，非 git 目录为 `unknown`）：
  ```
  build-index 完成：added=11143 skipped=0 total=11143
  backend=lancedb model=Xenova/multilingual-e5-small dim=384 pipelineRev=xxxxxxx
  store: count=11143 docTypes={"knowledge":94,"standard":57,"literature":142,"literature-full":9753,"table":1041,"enterprise":56}
  耗时 729000ms 左右
  ```
- **耗时**：约 **729 s**（11,143 块，e5-small，单机串行嵌入；首次还要下载模型）
- **产物**：
  - `data/index/lancedb/`（向量库，约 110 MB）
  - `data/index/manifest.json`（`embeddingModel` / `modelVersion` / `dim` / `pipelineRev` / 每块 `contentHash`）
  - `data/index/hf-cache/`（模型缓存，不入库）
- **可选：同时构建 SQLite 降级索引**（`golden-eval` 的 sqlite 后端与 e2e 降级测试使用；服务端 sqlite 后端的库路径不同，见 §9.3 与 FAQ #3）：
  ```bash
  HF_ENDPOINT=https://hf-mirror.com EMBEDDING_MODEL=multilingual-e5-small \
  pnpm build:index -- --rebuild --backend=sqlite --db-path=data/index/sqlite.db
  ```
  耗时约 605 s；若只做 LanceDB 演示可不建。
- **索引指纹**：T04 落地后 `pnpm exec tsx scripts/build-index.ts --check` 会生成 `docs/experiments/index-fingerprint.json`（`count / model / dim / manifestHash / pipelineRev / command / generatedAt`），可用于核对本地重建是否与基线一致；在此之前以 `data/index/manifest.json` 的 `chunks` 数量与 `dim` 字段核对。

> **幂等**：不加 `--rebuild` 重跑时，内容未变的块会跳过（`skipped`），只重嵌变化的块；`--rebuild` 强制全量重建。**换嵌入模型必须加 `--rebuild`**，否则会出现维度不匹配。

## 7. 跑评测

### 7.1 语料校验（秒级，无需索引）

```bash

```

### 7.2 检索金标准：三方案对比（38 条）

**前置**：已完成 §3 的 LanceDB 索引，且 `data/golden/golden.json` 未改动。

```bash
# 方案一：纯关键词 BM25（不加载嵌入模型，离线可用）
pnpm exec tsx scripts/golden-eval.ts lancedb --bm25

# 方案二：纯向量（把 BM25 权重置 0，只保留向量一路）
HYBRID_WEIGHTS=0,1 EMBEDDING_MODEL=multilingual-e5-small \
pnpm exec tsx scripts/golden-eval.ts lancedb

# 方案三：混合检索 RRF（默认，与生产一致）
EMBEDDING_MODEL=multilingual-e5-small \
pnpm exec tsx scripts/golden-eval.ts lancedb
```

也可用根脚本的别名：`pnpm eval:golden`（= 方案三）。

- **环境变量**：`EMBEDDING_MODEL`（查询向量必须与索引同模型）；`HYBRID_WEIGHTS`（方案二）
- **耗时**：每个方案约 1–2 分钟（含模型加载；纯 BM25 秒级）
- **预期结果**（整理时实测，达标条数 / 均值）：

  | 方案 | 命令开关 | 达标 | mean recall@5 |
  |---|---|---|---|
  | 纯 BM25 | `--bm25` | 35/38 | 0.857 |
  | 纯向量 | `HYBRID_WEIGHTS=0,1` | 36/38 | 0.882 |
  | 混合 RRF | 默认 | **38/38** | **0.9187**（doc 级 micro 82/91 ≈ 0.901） |

  输出末尾为 `通过 38/38（不达标 0）`；任一用例低于 `minRecallAt5` 时进程 **exit 1**（金标准回归门禁）。
  **口径提醒**：38/38 是「达标条数」而非召回率；报告引用时写 **mean 0.9187**。
- **落盘（可选）**：加 `--json` 输出机器可读结果，便于记录到 `docs/experiments/`：
  ```bash
  EMBEDDING_MODEL=multilingual-e5-small \
  pnpm exec tsx scripts/golden-eval.ts lancedb --json > /tmp/golden-hybrid.json
  ```

**前置**：§3 索引已构建（e2e 断言 `evidence > 0`）、§4 后端已在 3011 运行。

```bash

  ```

## 9. 端口策略与占用处理

### 9.1 端口分配

| 用途 | 推荐端口 | 相关变量 |
|---|---|---|
| 后端（Hono） | **3011** | `PORT` |
| 前端（Vite dev） | **5175** | 命令行 `--port 5175 --strictPort` |
| e2e 降级测试服务 | 3100 | 脚本内固定，无需配置 |
| 默认端口（可能被占） | 3000 / 5173 / 3010 / 5174 | `PORT` / vite 默认 |

三个变量必须指向同一后端端口：`PORT` = `API_PROXY_TARGET` 端口 = `E2E_BASE_URL` 端口。

### 9.2 检查与释放

```bash
# 查看占用
ss -ltnp | grep -E ':(3000|3011|5173|5175)\b' || echo "端口空闲"

# 释放被旧会话占用的端口（示例：3011）
fuser -k 3011/tcp
```

若不想 kill 别人的服务，直接换端口，并同步三处变量：

```bash
PORT=3012 API_PROXY_TARGET=http://localhost:3012 E2E_BASE_URL=http://127.0.0.1:3012 ...
```

### 9.3 SQLite 后端路径坑（重要）

- `pnpm build:index --backend=sqlite` 默认写 **`data/index/app.db`**；
- 但服务端 `RETRIEVAL_BACKEND=sqlite` 读的是 **`data/index/sqlite.db`**。

两者不一致时，`/health` 会显示 `count: 0`（空库），检索无结果。处理方式二选一：

```bash
# 方式一：显式把索引建到服务端读取的路径
pnpm build:index -- --rebuild --backend=sqlite --db-path=data/index/sqlite.db

# 方式二：演示统一用 LanceDB（默认后端）
RETRIEVAL_BACKEND=lancedb
```

## 10. 降级矩阵（依赖不可用时会发生什么）

| 依赖不可用 | 系统行为 | 如何验证 |
|---|---|---|
| LLM 未配置 / `LLM_OFF=1` / 余额不足（402） | 报告与问答降级为模板/抽取式文案；`llmStatus: degraded`；检索与确定性计算不受影响 | `curl /api/v1/health` 的 `llm.configured=false`；`pnpm e2e` 的降级用例 |
| 嵌入模型下载/加载失败 | 检索降级为**纯 BM25**，服务不崩 | 启动日志 `检索降级纯 BM25` |
| LanceDB 初始化失败 | 自动降级 SQLite（`data/index/sqlite.db`） | 启动日志 `LanceDB 初始化失败，自动降级 SQLite` |
| 关系库缺失/为空 | 启动时从 `data/corpus/` 自动种子（幂等） | 日志 `关系表为空，从 data/corpus 种子……` |
| A/C 队友服务端点不可达 | 推荐链路用内置 mock，`adapterMode` 显示 `mock`，报告带「模拟数据」角标 | 报告字段 `adapterMode.a/c` |
| 索引为空/不存在 | `/health` 的 `ok=false`、`count=0`；检索无结果（问答应走拒答） | `curl /api/v1/health` |

## 11. FAQ / 故障排查

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | 请求返回 `HTTP 402 Insufficient Balance`；日志出现重试≈7 s | DeepSeek 账户余额为 0 | 充值、换 OpenAI 兼容端点，或 `LLM_OFF=1` 演示降级（报告中注明「LLM 不可用」） |
| 2 | 启动/检索报「维度不匹配」或 LanceDB 查询报错 | 索引是 e5-small（384 维），启动却用了默认 `bge-m3`（1024 维） | 启动与建索引**使用同一个** `EMBEDDING_MODEL`；换模型必须 `--rebuild` 全量重建 |
| 3 | `/health` 显示 `count: 0`，检索无结果 | `data/index/` 不存在（新仓库不含索引），或 sqlite 库路径不一致（§9.3） | 先 `pnpm build:index`；sqlite 后端用 `--db-path=data/index/sqlite.db` 重建 |
| 4 | `tsx: command not found` | 直接调用了裸 `tsx`（本机无全局安装） | 一律用 `pnpm exec tsx scripts/xxx.ts`，或用根脚本 `pnpm build:index` / `pnpm e2e` / `pnpm eval:golden` |
| 5 | `pnpm e2e` 断言失败：HTTP 非 200 / 连到别的服务 | 默认打 `http://127.0.0.1:3000`，该端口可能被 grafana 等占用 | 设置 `E2E_BASE_URL=http://127.0.0.1:3011` |
| 6 | 前端页面能开但接口 404/502 | `API_PROXY_TARGET` 指向的后端端口不对 | 与后端 `PORT` 对齐后重启前端 dev server |
| 7 | 首次建索引卡在下载模型 / 报网络错误 | 无法访问 HuggingFace | 设 `HF_ENDPOINT=https://hf-mirror.com`；或预置 `data/index/hf-cache/` 后离线运行；实在不行可只用纯 BM25（`--bm25`）演示检索 |
| 8 | 端口占用（`EADDRINUSE`） | 3000/3010/5173/5174 残留进程 | 改 3011/5175（§9），或 `fuser -k <port>/tcp` |
| 9 | `pnpm` 命令开头长时间卡住 | pnpm 12 运行前依赖校验；离线时 postinstall 重试 | 等待其继续（约 1–2 分钟）；确保 `node_modules` 完整后可正常执行 |
| 10 | Node 22 下 sqlite 后端报「Cannot find module 'node:sqlite'」 | `node:sqlite` 需 Node ≥ 24 | 升级 Node；或改用 `RETRIEVAL_BACKEND=lancedb` |
| 11 | `pnpm exec tsx scripts/golden-eval.ts` 直接退出 1 | 有用例低于 `minRecallAt5`（门槛是红线） | 先确认索引块数 = 11,143、`EMBEDDING_MODEL` 一致；不要为了过门禁改门槛 |
| 12 | 问答接口返回 `501 {"status":"not_implemented"}` | 问答链路尚未实现（当前为骨架） | 属于预期状态；见 [任务拓扑](plan/task-topology.md) S1/S2 里程碑 |

## 13. 各步骤耗时与资源预估

| 步骤 | 耗时（实测/预估） | 说明 |
|---|---|---|
| `pnpm install` | 1–3 min | 首次含原生依赖 |
| `pnpm build:index`（lancedb，e5-small） | **≈ 729 s** | 11,143 块；首次含模型下载 |
| `pnpm build:index`（sqlite） | ≈ 605 s | 可选 |
| 后端启动 | 3–15 s | 模型缓存命中时更快 |
| 前端启动 | 2–5 s | — |
| `pnpm test` | 1–2 min | 单测不需要索引 |
| `golden-eval` 单方案 | 1–2 min | 含模型加载；纯 BM25 秒级 |
| `pnpm e2e` | 2–5 min | 含降级服务启动 |
| 磁盘占用 | ≥ 2 GB | 依赖 + 模型缓存 + 索引 |
