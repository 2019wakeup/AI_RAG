# 参数说明（config/params.json）

> 超参数的唯一登记处是 [`config/params.json`](../config/params.json)。本文与它**逐键一一对应**（测试 `apps/server/test/params.test.ts` 自动比对，缺一即红）。
> 优先级：**环境变量 > params.json 的 default > 代码内兜底**；非法值在启动时直接抛错并退出（不进入半可用状态），与 `EMBEDDING_MODEL` 的校验行为一致。

## 1. 通用规则

```bash
# 覆盖示例：把 RRF 常数改成 80、开启 MMR
RRF_K=80 MMR=on pnpm -C apps/server run dev

# 自定义参数文件（隔离实验，不污染仓库默认值）
PARAMS_PATH=/tmp/my-params.json pnpm -C apps/server run dev
```

- 数值参数：越界或非数字 → 启动失败，报错信息带上参数键、实际值与 range；
- 布尔参数：接受 `1/0/true/false/on/off/yes/no`；
- 字符串参数：原样透传（如 `retrieval.hybridWeights` 的 `"1,1"`，格式校验在 `packages/retrieval` 的 `parseHybridWeights`）；
- 修改 params.json 属于平台改动（A 评审），`owner` 字段表示该参数由谁负责解释与调参。

## 2. 参数表

| 参数键 | 默认值 | 范围 | 环境变量 | 负责人 | 说明 |
|---|---|---|---|---|---|
| `retrieval.rrfK` | 60 | [1, 200] | `RRF_K` | A | RRF 融合常数 k；越大越平滑、越小越偏向头部 |
| `retrieval.hybridWeights` | "1,1" | — | `HYBRID_WEIGHTS` | A | RRF 两路权重（bm25,vec）；`0,1`=纯向量，`1,0`=纯关键词 |
| `retrieval.candidateTopK` | 20 | [1, 100] | `CANDIDATE_TOP_K` | A | 检索候选池大小（重排/证据挑选的输入） |
| `retrieval.rerankTopK` | 6 | [1, 50] | `RERANK_TOP_K` | A | 每个查询保留给重排的命中条数 |
| `retrieval.rerankTimeoutMs` | 8000 | [500, 60000] | `RERANK_TIMEOUT_MS` | A | LLM 批量重排超时；超时回退 RRF 原序 |
| `retrieval.mmrEnabled` | false | — | `MMR` | A | 是否启用 MMR 多样性选择（默认关闭，数据驱动结论） |
| `retrieval.mmrLambda` | 0.7 | [0, 1] | `MMR_LAMBDA` | A | MMR 相关性/多样性权衡 λ |
| `retrieval.mmrPool` | 6 | [1, 50] | `MMR_POOL` | A | MMR 候选池大小（默认 = 重排 top-K） |
| `evidence.perCandidate` | 3 | [1, 10] | `EVIDENCE_PER_CANDIDATE` | A | 每个推荐候选配几条证据 |
| `evidence.globalReuseCap` | 3 | [1, 20] | `EVIDENCE_REUSE_CAP` | A | 同一知识块在所有候选中的最大复用次数 |
| `evidence.quota.knowledge` | 2 | [0, 10] | — | A | 证据配额：知识条目 |
| `evidence.quota.standard` | 1 | [0, 10] | — | A | 证据配额：规范条文 |
| `evidence.quota.table` | 1 | [0, 10] | — | A | 证据配额：定量表格 |
| `evidence.quota.literature` | 2 | [0, 10] | — | A | 证据配额：文献题录/全文章节 |
| `evidence.quota.enterprise` | 1 | [0, 10] | — | A | 证据配额：企业资料 |
| `qa.minHits` | 3 | [1, 50] | `QA_MIN_HITS` | C | 拒答判据①：检索命中数下限（低于即拒答 no_hit） |
| `qa.minScore` | 0.35 | [0, 1] | `QA_MIN_SCORE` | C | 拒答判据②：最高原始相似度下限（低于即 low_relevance） |
| `qa.minCoverage` | 0.5 | [0, 1] | `QA_MIN_COVERAGE` | C | 拒答判据③：证据覆盖问题要素的比例下限 |
| `qa.topK` | 8 | [1, 20] | `QA_TOP_K` | B | 问答检索返回的候选条数 |
| `qa.maxAnswerChars` | 1200 | [100, 5000] | `QA_MAX_ANSWER_CHARS` | B | 答案长度上限（超出截断并标注） |
| `sort.penaltyBudgetPerWan` | 0.02 | [0, 0.5] | — | A | 推荐排序：预算每超 1 万元的扣分 |
| `sort.penaltySchedulePerDay` | 0.01 | [0, 0.5] | — | A | 推荐排序：工期每超 1 天的扣分 |

> `—` 表示该参数只能通过 `params.json` 修改（不开放环境变量，避免演示时被临时覆盖导致结论不可复现）。

## 3. 谁读这些参数

| 参数组 | 消费方 | 现状 |
|---|---|---|
| `retrieval.*` | `packages/retrieval`（RRF/权重由 `parseHybridWeights` 读取 env）、`apps/server/src/rag/rerank.ts`（超时）、`apps/server/src/orchestrator.ts`（MMR λ/池） | ✅ T03 已接入：rerank 超时、MMR λ/池；RRF k 由检索包默认值 60 对齐 |

| `qa.*` | `apps/server/src/qa/`（T08/T09/T17/T18） | 🟡 已预留，C 的 `decideRefusal()` 直接 `getNumber('qa.minScore')` 等 |
